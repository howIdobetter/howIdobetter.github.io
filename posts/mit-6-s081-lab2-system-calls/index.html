为什么不写 lab1 的题解呢，因为 lab1 其实相当于习惯调用函数的使用，并且偏向 user applications 的编写，实际上并没有系统强相关的内容。

System call tracing

这个有相当一部分难度，但是题目已经将 user application 的代码在 user/trace.c 中给出了，因此能让我们专注于系统调用的 tracing 部分。编写一个系统调用需要更改内核代码，因此需要小心一些，不然很容易出现难以想象的 bug。

题目只给了 trace.c，因此从 lab1 我们知道需要在 Makefile 中加入 $U/_trace才能将这个 user application 编译进 xv6 中。

然后我们首先从用户态出发，用户态调用的是 trace 系统调用函数，因此需要在 user/user.h 中加入 int trace(int); 的函数声明。在 usys.plusys.plusys.pl 脚本中，这个其实就相当于批量生成命令，我们看

sub entry {
    my $name = shift;
    print ".global $name\n";
    print "${name}:\n";
    print " li a7, SYS_${name}\n";
    print " ecall\n";
    print " ret\n";
}

加入一个 entry(trace)就会生成：

.global trace
trace:
 li a7, SYS_trace
 ecall
 ret

从而进入内核态的 syscall 函数中，syscall 函数中会根据 a7 的值来调用对应的系统调用函数，因此我们需要在 kernel/syscall.c 中加入：

extern int sys_trace(void);

[SYS_trace]   sys_trace,

此外还需要在 kernel/syscall.h 中加入：

#define SYS_trace 22

此时基础的系统调用已经完成了，接下来我们需要在 kernel/sysproc.c 中实现 sys_trace 函数。

uint64
sys_trace(void)
{
  int mask;
  if (argint(0, &mask) < 0)
    return -1;
  myproc()->trace_mask = mask;
  return 0;
}

然后由于我们需要跟踪所有进程的系统调用，因此我们需要在 proc.h 中加入：

int trace_mask; // trace mask for system call tracing

然后在 kernel/proc.c 中的 fork 函数中加入：

  p->trace_mask = myproc()->trace_mask;

最后我们需要在 kernel/syscall.c 中的 syscall 函数中加入：

void
syscall(void)
{
  int num;
  struct proc *p = myproc();

  num = p->trapframe->a7;
  if(num > 0 && num < NELEM(syscalls) && syscalls[num]) {
    p->trapframe->a0 = syscalls[num]();
    if ((1 << num) & p->trace_mask)
      printf("%d: syscall %s -> %d\n", p->pid, syscall_names[num], p->trapframe->a0);
  } else {
    printf("%d %s: unknown sys call %d\n",
            p->pid, p->name, num);
    p->trapframe->a0 = -1;
  }
}

值得注意的是为了简便，我们在 kernel/syscall.c 中加入了一个 syscall_names 数组来存储系统调用的名字：

static char* syscall_names[] = {
  "none",
  "fork", "exit", "wait",
  "pipe", "read", "kill",
  "exec", "fstat", "chdir",
  "dup", "getpid", "sbrk",
  "sleep", "uptime", "open",
  "write", "mknod", "unlink",
  "link", "mkdir", "close",
  "trace"
};

Sysinfo

我们按照 System call tracing 的思路添加 sysinfo 系统调用，这里不过多赘述了。

难点主要在于 copyout 函数的使用，sysinfo 需要返回一个 struct sysinfo 的结构体，因此我们需要在 kernel/sysproc.c 中实现 sys_info 函数：

uint64
sys_info(void)
{
  uint64 addr;
  struct sysinfo info;
  struct proc *p = myproc();
  if (argaddr(0, &addr) < 0)
    return -1;
  info.freemem = freemem();
  info.nproc = nproc();
  if ((copyout(p->pagetable, addr, (char *)&info, sizeof(info)) < 0))
    return -1;
  return 0;
}

然后就是 freemem 和 nproc 函数的实现了，freemem 需要遍历内存页表来计算空闲内存页的数量，nproc 需要遍历进程表来计算当前活跃的进程数量。freemem 可以参照 kalloc 寻找空闲页的方式来实验，注意每一页的大小为 PGSIZE，nproc 可以参照 allocproc 寻找空闲进程的方式来实验，注意每个进程的状态为 UNUSED 时表示该进程槽位是空闲的，这里需要寻找的是 非 UNUSED 的进程槽位。

分别实现为：

uint64
freemem(void)
{
  struct run *r;
  uint64 count = 0;

  acquire(&kmem.lock);
  r = kmem.freelist;
  while (r) {
    count++;
    r = r->next;
  }
  release(&kmem.lock);
  return count * PGSIZE;
  return 0;
}
uint64
nproc(void)
{
  struct proc *p;
  int count = 0;
  for (p = proc; p < &proc[NPROC]; p++) {
    acquire(&p->lock);
    if (p->state != UNUSED) {
      count++;
    }
    release(&p->lock);
  }
  return count;
}
